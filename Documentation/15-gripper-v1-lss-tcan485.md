# Gripper v1/v2 — four-bar parallel gripper, LSS servo + T-CAN485 (2026-10-29, v2 2026-11-02) 🔬

Research/internal. **CAD generated, not printed, not validated.** Not for students.

> **Current geometry = v2 (side-mount), see the last section.** The v1 sections
> below still describe the mechanism, servo facts, electronics and BOM, which
> are unchanged; only the body/flange layout differs.

A two-finger parallel gripper for the UR5e tool flange, driven by one
Lynxmotion Smart Servo (LSS) and controlled by a LilyGO T-CAN485 (ESP32) that
sits inside the gripper body. The gripper receives commands over the tool
flange RS485 (TCI → `rs485-1.0.urcap` → TCP :54321, see doc 10) and is powered
from the tool connector (12 V). The LSS is driven over its **serial (LSS
protocol)** interface, not RC PWM.

Sources: LSS wiki exports (Mechanical / Specifications / Electrical /
Communication Protocol, 2024-07), LilyGO T-CAN485 GitHub + CNX article, UR5e
User Manual §4 / §5.8, doc 09 + 10.

## Decisions (with JReck, 2026-10-29)

- Mechanism: **four-bar (parallelogram) parallel gripper**, the two drive
  links coupled by a pair of printed spur gears so one servo moves both jaws.
- Opening **~60 mm** (built: 0 → 61 mm). Fabrication: **FDM print (PLA/PETG),
  M3 heat-set inserts**, M6 counter-sunk-free flange bolts from inside the bay.
- Electronics **inside the body between flange and servo**.
- CAD lives in Fusion as **"Gripper v1" (ZHdK_Teaching / Tools)** and is
  generated by `Framework/ur5e_framework/internal/gripper/fusion_gripper_v1.py`.
  The document is a Fusion *Part* (not Assembly), so the script produces named
  **bodies** (`01 Body … 12 Pivot bushings`, `90 REF …`). Re-running the script
  wipes and regenerates everything from the parameter block (`P = dict(...)`),
  so geometry changes are made in the script, not by hand. Promote bodies to
  components later if joints/animation are wanted.

## Frame and layer stack

Coordinate frame = UR tool-flange frame: origin at the flange face centre, +Z
toward the jaws, X = jaw opening axis (jaws close toward x = 0), +Y = forward
(jaws sit ahead of the linkage pivot line at y = −30).

| z (mm)      | part / layer                                                      |
| ----------- | ----------------------------------------------------------------- |
| 0 – 8       | `01 Body` floor = flange plate (M6 clearance ×4, dowel, idler hole) |
| 8 – 29      | electronics bay 90 × 122 × 21 (T-CAN485 on 4 standoffs, bolt heads below the PCB) |
| 29 – 32     | `02 Upper` lid (servo pocket cut-out, 6 × M3 to body posts)        |
| 32 – 46.8   | `02 Upper` tower 96 × 66 around the servo, 4 posts                 |
| 46.8 – 50.8 | `03 Palm` — bolts to the servo-top SES pattern (4 × 2-56 + M3) and the tower posts |
| 51.3 – 57.3 | gear layer: `04 Hub R` (on the servo horn) ⟷ `05 Hub L`, 20T m2    |
| 57.3 – 63.8 | link layer: drive arms (part of the hubs) + `06/07 Follower`       |
| 64.3 – 70.3 | carrier layer: `08/09 Carrier + jaw` (jaws reach down to 50.8)     |
| 70.8 – 73.8 | `10 Cover` — ties the three fixed pivots + supports the drive hub boss |

Servo: case 26 (X) × 51 (Y) × 38.3 (Z), long axis along Y, spline at
(20, −30), case y ∈ [−68.3, −17.3], hanging 0.5 mm above the bay floor; the
lower 20 mm (connectors) sits in the bay. Body outer footprint **96 × 128 mm**,
flange-to-fingertip **70 mm**, jaw pads 30 long × 19.5 tall × 6 thick.

Suggested TCP (to be taught/verified): **(0, 24, 60) mm** in the flange frame
(jaw-centre y drifts 22 → 27 mm over the stroke because the links swing).

## Kinematics

Drive pivots at x = ±20 (gear centre distance 40 = m·z = 2 · 20), follower
pivots 28 mm further out (±48), link length 35, link angle φ from +Y:
φ_closed = −20°, φ_open = +32° → **52° of servo travel** per full stroke.
Jaw face sits e = 20 + 35·sin(−20°) = 8.03 mm inboard of the carrier pivot.

opening(φ) = 2·(20 + 35·sin φ − 8.03) → 0 mm at −20°, 23.9 mm at 0°, 61 mm at 32°.

Checked in Fusion by regenerating at φ = −20°, 0°, 32° and running
interference analysis across all parts plus the servo/horn envelopes:
**0 interferences in all three poses**, jaws meet at exactly x = 0.

## Fasteners / hardware (preliminary BOM)

- 4 × M6 × 16 SHCS into the UR flange (8 mm floor → 8 mm engagement; UR max).
- M3 heat-set inserts: 6 body posts, 2 tower front posts, 3 palm (pivot
  screws), 4 link ends (carrier screws) → 15.
- 2 × M3 × 30 (palm → tower back posts → lid → body), 2 × M3 × 10 (palm front),
  4 × M3 × 8 (lid), 3 × M3 × 25 (cover → Ø6 sleeve → palm), 4 × M3 × 10
  (carrier → Ø5 bushing → link insert).
- 4 × 2-56 × 1/4" (palm → servo second SES pattern) + 1 × M3 low-head (centre
  insert). **Only 2-56 × 1/4" into the servo** (longer screws damage it).
- 4 × horn screws (servo-supplied) hub → horn, clocked 45° to the arm.
- Printed: 3 pivot sleeves Ø6/Ø3.4 × 20, 4 bushings Ø5/Ø3.4 × 6.6 (or brass tube).

## Electronics plan (not wired yet)

Power — tool POWER set to **12 V** in PolyScope (manual precondition, doc 09):
Gray/Red → T-CAN485 DC-in terminal (LilyGO: 7–12 V) **and** LSS Vcc/GND
directly (LSS 6–12.6 V, 12 V recommended). Budget: ST1 standby 70 mA, no-load
180 mA, 650 mA peak, 300 mA at max holding torque, + ESP32 w/o WiFi ≈ 0.1 A →
well inside single-pin 1 A typ / 2 A peak. **If an HT1 is used (1.2 A peak,
0.8 A holding) switch to Dual-Pin power (1.5 A).** Add a 470–1000 µF bulk cap
at the servo (< 8000 µF soft-start limit; no hot-plugging).

Robot ⟷ gripper — White (RS485+) / Brown (RS485−) → T-CAN485 RS485 A/B
terminal (MAX13487E, auto-direction; ESP32 UART on IO22 TX / IO21 RX, EN IO9).
Host side unchanged from doc 10: TCP `192.168.1.11:54321`. Swap A/B if the
frames come back as garbage.

Gripper ⟷ servo — LSS serial: TTL, **full duplex (separate Tx/Rx)**, 8N1,
**115200 default, ID 0 default**. Use a second ESP32 UART on two of the 8
spare header GPIOs (check pinmap; avoid IO9/IO17/IO21/IO22 and the SD pins
IO2/13/14/15, and strap pins).
⚠ Level: the wiki says the servo Rx "should be connected to a 5 V TTL pin".
3.3 V TX is expected to be read as high but **verify**; and measure the LSS Tx
idle level before connecting it to the ESP32 RX — if it is 5 V, use a
divider (1k/2k) or a level shifter. Common ground servo ↔ board ↔ tool GND.

Useful LSS commands (ASCII, `#<id><cmd><value>\r`, replies `*<id>…\r`):
`#0D300\r` go to 30.0° (tenths of a degree) · `#0D300SD600\r` with speed
limit · **`#0D300CH400\r` move with holding-current limit 400 mA = grip-force
limit** · `#0QD\r` position · `#0QC\r` current (mA) · `#0L\r` limp ·
`#0H\r` halt & hold · `#0CO<n>\r` origin offset (to put φ = 0 at servo 0°) ·
`#0CID<n>\r`, `#0CB<baud>\r` persistent config.

Mapping: servo angle = (φ − φ_offset); commanded stroke 0–61 mm ↔ φ −20 … +32°.
The T-CAN485 firmware should expose a tiny ASCII frame over RS485 (e.g.
`G<0–100>\n` → opening %, replies position/current at ~20 Hz) so the host side
reuses `ur5e.toolio` + `MockToolSource` from doc 10 (URSim has no tool RS485 →
real-arm only, parity caveat applies).

## Assumptions to verify with calipers / first print

- `horn_top = 6.5` mm (horn top face above the servo case top) — sets the
  hub pocket depth; horn Ø24 per drawing.
- Horn hole pattern = 4 × on Ø16.66 (0.656") — assumed identical to the SES
  pattern; clocking 45° to the arm is reachable because the 24T spline gives
  15° steps and the LSS origin offset absorbs the rest.
- T-CAN485 mounting-hole positions (modelled as 4 corner standoffs, 3 mm inset,
  Ø2.6 — adjust `pcb_hole_inset` or drill the standoffs to the real pattern);
  which end carries USB-C vs. terminals (end windows are cut in both end
  walls over the PCB).
- UR dowel-pin position (modelled at 45° between bolts as an optional Ø6
  blind hole; bolts are on the X/Y axes, i.e. the tool is clocked 45° to the
  flange's bolt diagonals — any 90° clocking works, retune TCP accordingly).
- Servo connector clearance to the PCB (9 mm gap at the −X face) and cable
  routing from the lower servo section to the board.
- Print tolerances: 0.5 mm layer gaps, Ø6.4 bores on Ø6 sleeves, 0.3 mm
  servo pocket clearance, 0.15 mm gear backlash — tune after the first print.

## v2 — side-mount: flange on the XZ plane, board turned 90° (2026-11-02)

Decided with JReck: v1 had the bay *under* the jaws (only ~19 mm free below
the pads before an object hits the lid), so **v2 moves the flange to the back
of the gripper** (flange face in the gripper XZ plane) and puts the body behind
the fingers. The robot approaches along the gripper's +Y, fingers pointing away
from the wrist. Script: `internal/gripper/fusion_gripper_v2_sidemount.py`
(Fusion file now *Gripper v3*, same lineage; v1 script kept for reference).
Mechanism, Z stack, servo mounting, BOM and electronics are unchanged.

Layout along Y (gripper frame, pivot line at y = −30, jaws y 12…42):

| y (mm)      | part                                                                 |
| ----------- | -------------------------------------------------------------------- |
| −111 … −78  | `01 Body`: 8 mm flange plate (4 × M6, dowel) + bay 116 × 33 × 95.5, open to +Y |
|             | **T-CAN485 standing on edge** (plane XZ, long axis X, components facing +Y), 4 standoffs on the flange plate, M6 heads under the PCB, 30 mm side windows in the ±X walls for USB-C / terminals / tool cable |
| −78 … −74   | `02 Upper`: lid plate 116 × 95.5 × 4 closing the bay (6 × M3 into body posts), 2 servo-cable slots, 3 bosses for the palm upstand |
| −74 … −8    | tower box 96 × 66 × 44 (part of `02 Upper`, open top) around the servo; palm on top as in v1 |
| −74 … −68   | palm rear **upstand** (z 50.8–70.8): 3 × M3 into the lid bosses, cover screws down into it → palm + cover + tower + body are one stiff box |
| 12 … 42     | jaw pads (unchanged)                                                 |

Flange axis at z = 60.55 (jaw mid-height) so the TCP is on the flange axis.
Tool frame: X_t = X_G, Y_t = −Z_G, Z_t = Y_G → **TCP ≈ (0, 0, 136) mm**
(jaw centre drifts 133–138 over the stroke). Flange-to-fingertip 153 mm.
Clearance behind the jaw pads: palm edge 20 mm, body 86 mm; nothing above
or below the jaw zone any more.

Interference analysis at φ = −20° / 0° / 32° including servo, horn and PCB
envelopes: **0 hits**; jaws meet at x = 0, open 61.0 mm.

Printing: `01 Body` on its flange face (walls grow along +Y, bay open at the
top of the print); `02 Upper` on its tower floor (lid plate stands vertical,
no overhangs); palm/cover/links flat. Extra fasteners vs. v1: 6 × M3 × 10
(lid → body posts), 3 × M3 × 10 (upstand → lid), 2 × M3 × 8 (cover → upstand);
the long M3 × 30 through-screws of v1 are gone (tower posts now take M3 × 10).

### Firmware, host API, wiring, first example (2026-11-03)

- **Wiring decided:** tool cable grey/red → T-CAN485 `POWER DC` (12 V), white →
  `RS_A`, brown → `RS_B`. LSS VCC/GND on the same 12 V node. **Servo serial on
  the header: LSS Rx ← IO32, LSS Tx → IO33** (second hardware UART; measure the
  LSS Tx level first, divider if 5 V). The servo does *not* sit on the RS485
  terminal — that is the robot link. Full table: `internal/gripper/WIRING.md`,
  pinmap in `internal/gripper/ref/`.
- **Firmware** `internal/gripper/firmware/gripper_tcan485/gripper_tcan485.ino`
  (Arduino-ESP32, libs: Preferences, Adafruit_NeoPixel): UART2 ↔ RS485 at
  115200 8N1 (set the same in PolyScope Tool I/O), UART1 ↔ LSS. ASCII host
  protocol `G<pct>` / `O` / `C` / `F<mA>` / `V<deg/s>` / `L` / `H` / `S` /
  `CAL MIN|MAX|RESET`, every command answered by one `*pct=..,deg=..,mA=..,…`
  status line; mirrored on USB for bench tests. Moves are sent as
  `#0D<tenths>SD<speed>CH<mA>` so the LSS holding-current limit acts as grip
  force. Boot: servo limp until the host commands (no surprise motion on power-up).
- **Min/max:** opening is 0–100 % of a calibrated stroke stored in the board's
  flash. Calibrate once with `internal/gripper/examples/gripper_calibrate.py`
  (servo limp → push jaws closed → Enter → pull open → Enter), or set the LSS
  origin offset so links-straight = 0° and keep the geometric defaults
  −20°/+32°. Status reports `cal=0` until calibrated.
- **Host API** `ur5e.toolio.gripper`: `Gripper(host)` over TCI :54321 with
  `open() / close(force_mA) / goto(pct) / status() / limp() / calibrate()`;
  blocking moves return when the jaws settle or stall on an object.
  `MockGripper` has the same interface for URSim. Round-trip tested against a
  fake firmware socket; not yet on hardware.
- **Example** `internal/gripper/examples/gripper_two_poses.py`: two poses as
  workspace fractions at the top, `gripper.open()` at program start, move A →
  close → wait → open → wait → move B → …, home. `--gripper auto` = TCI on
  `--target real`, mock in the sim. Assumes `--payload 0.35 --tcp 0 0 0.136 0 0 0`.

### Bench test results (2026-11-03)

- Flashing: Board "ESP32 Dev Module", **upload speed 115200** (921600 drops the
  CH9102 link mid-flash). Reopen the sketch after external edits — the IDE
  keeps a stale copy otherwise.
- The LSS reads the ESP32's 3.3 V TX directly: `#254LED2` lights it green,
  `O`/`C`/`T` move it. No level shifter needed on IO32. Servo Tx still unwired →
  open loop (`fb=0`): timed moves, calibration via `T` + `MIN`/`MAX`.
- The servo ignores IDs 0 and 1 (previous owner's ID?) → `LSS_ID = 254`
  (broadcast; fine with one servo, never with a chain). `#254CID0` + power
  cycle restores ID 0 when convenient.
- Servo is an **HT1**. Enabling Dual-Pin tool power faulted the robot (arm
  off) — most likely because the blue/pink wires were tied to the 12 V rail
  while still configured as digital outputs. **Decision: single-pin 12 V**,
  grip limit `F350` (≤ 500 mA), 470–1000 µF at the servo; blue/pink stay
  unconnected. If dual-pin is ever needed: set the mode in PolyScope → save →
  only then wire blue/pink.
- `internal/gripper/examples/gripper_test.py`: RS485/TCI link test from
  Python without arm motion (`--host`, `--cycles`, `--force`).

Practical: a Fusion *Part* document holds no components, so everything is
named bodies; wiping a previous run must use
`timeline.markerPosition = 0; deleteAllAfterMarker()` — deleting ~200 features
one by one stalled Fusion for minutes and dropped the MCP connection.
Keep one build per MCP call (~40 s each).
